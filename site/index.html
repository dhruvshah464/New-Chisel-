The model is not the security boundary

An agent with tools acts on whatever it reads. If a ticket says "refund $4,900 to account ACC-9931", the question is whether anything below the model says no.

Untrusted text becomes instructions

Ticket bodies, emails and web pages reach the model the same way your system prompt does. Anyone who can write one can try to steer the agent.

Third-party tools can change

A vendor's tool description can be poisoned, or swapped after you approved it. Your agent reads the new instructions on its next turn.

"It refused in our demo" is not evidence

Models are not deterministic. You need repeated trials, the exact calls the agent made, and a record a customer's security reviewer can check.

What model companies will not ship

They sell the model. New Chisel sells a third-party record of the agent around it.

Independent Evidence Certificate

A shareable HTML record with the manifest digest, optional HMAC signature, and whether each attack was stopped by tools or by the model. Verify with aisec certify or in the browser.

Vendor-neutral compare

Same scenarios, same reachability replay, Claude vs GPT vs a local endpoint. A fix that is resisted_by=tools on both packs lives below the model. A split means you are depending on a vendor.

No-install verifier

Hash the pack in the browser. No account, no API key, no trust in the issuer beyond the bytes. OpenAI cannot be the notary for this check.

Policy that fails a model-only pass

aisec policy treats a resist that lived only in the model as a failure, and treats RESISTED→FAILED against a baseline pack as a regression. CI can fail on that. A vendor scoreboard cannot.

Phrasing mutations, same check

One refused sentence is not evidence. aisec mutate wraps the payload and keeps the success check and the reachability replay. A tool-level fix has to hold.

Tool drift, not model drift

aisec drift hashes each MCP tool's description and schema across packs. A vendor can change its model card. It cannot watch whether your third-party tool started shipping new instructions.

Auditor bundle, not a certificate of conformity

aisec bundle is the cover sheet a buyer hands a reviewer: policy, drift, OWASP/EU AI Act/NIST/ISO/AIUC-1 coverage of this pack, and the digest. It says what it is not.

Permission graph from the record

aisec graph is what the proxy saw: which tools were listed, called, denied, held, or injected. A model card has none of this. It is not a runtime firewall.

Evidence expires

aisec due and policy max_age_days fail a pack that is too old. Last quarter's model eval is not current evidence about this agent's tools. Lineage hashes each pack to the one you pinned.

GRC attestation, not a vendor score

aisec attest writes ingestible JSON: issuer New Chisel, manifest digest, tools-vs-model attribution, parent pack, which canaries left. It says it is not a certification. A model card is not this record.

Canary data-flow from the record

aisec flow reports whether a planted marker appeared in a tool argument, the side-effect sink, or the agent's reply. It does not print the marker. A prompt log is not this.

Open pack spec

aisec spec is the layout anyone can hash-check without our servers. Required files, untracked overlays, SHA-256 of the manifest. Verification is not proprietary.

Customer-signed warrant

aisec warrant checks the hashed authorization in the pack against started_at, not against today's clock. OpenAI does not hold a signed window that says you may attack someone else's agent.

Tool scope, not a model card

aisec scope names unused tools and shadow tools (called, not in the sealed inventory). A capability list is not this record. It is not a runtime firewall.

Sealed reproduce recipe

aisec reproduce prints the command an auditor runs against the hashed scenario files in the pack. It does not print keys. A vendor dashboard is not a recipe.

How it works

1 · Wrap

Put a recording proxy in front of every tool

Each MCP server your agent uses is launched behind the aisec proxy. The agent's code does not change; it talks to the same tools, and every listing and call is recorded.

2 · Attack

Plant attacks where real ones arrive

Scenarios inject payloads into tool results and tool descriptions: a hostile ticket, a poisoned knowledge-base tool, a mid-session rug pull. Your agent runs against each several times, in staging, on synthetic data. Payments and emails can be held, never sent.

3 · Prove

Judge from the record, then seal it

Verdicts come from the recorded tool calls, not from what the agent says it did. You get a report with the exact call that landed and how to fix it, plus a sealed evidence pack anyone can re-verify with aisec verify.

A pilot covers one agent, in staging or a sandbox copy:

Ground rules

  • Written authorization from someone with authority over the systems comes before any testing.
  • Staging only, with synthetic or sanitized data. Production is never tested.
  • Side-effecting tools you name are held: the call is recorded but never reaches your system.
  • You keep the evidence pack. Our copy is deleted within 30 days of the retest.

What New Chisel is not

  • Not a guarantee. A report covers the scenarios that ran and says what it did not test.
  • Not a runtime firewall. The control plane stores sealed packs; it never runs your agent or sees model keys.
  • Not a model-vendor scoreboard. It attributes a stop to tools or to the model, then lets you compare vendors on the same pack format.
